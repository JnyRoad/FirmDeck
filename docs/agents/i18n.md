# 国际化治理规则

本文件是开发者和开发 Agent 的可执行规则。架构边界见根 `CONTEXT.md` 以及
`docs/adr/ADR-001-i18n-runtime-and-catalog.md`；本规则不把局部测试通过表述为全仓完成。

## 必须本地化的内容

开发者拥有的每一处产品消息都必须进入语义 i18n 入口，并在每个正式支持语言中提供。这不
只包括普通 JSX 文本，还包括：

- 页面/路由标题、导航、菜单、按钮、标签、表格、图表、筛选器、分页和空/加载/错误状态；
- 表单标签、placeholder、校验、帮助、`aria-*`、`title`、`alt`、`data-*` 中用于用户提示的值；
- Toast、Sonner、弹窗、原生 `alert`/`confirm`/`prompt`、剪贴板提示、下载名中的产品前缀；
- iframe/postMessage 外壳、通知、异步任务状态、后端错误/事件投影和非 DOM 输出；
- Agent 运行界面中由 FirmDeck 生成的阶段名、工具状态、系统提示和错误，而不是 Agent/工具的
  原始业务内容。

## 消息键、目录与参数

- 所有消息键必须是稳定、可理解的英文语义 ID，使用业务命名空间和 lower camel case，例如
  `billing.invoice.itemCount`、`shell.nav.knowledge`。代码标识符和语义键使用英文；英文或
  中文文案不是键，placeholder 名称也不是键。
- 禁止 `t('保存成功')`、`t('Save successfully')`、``t(`user.${type}.message`)``、
  ```${count} item(s)``` 以及用用户数据拼出 `id`。复数/选择必须留在 ICU 消息中。
- `en-US` 是 canonical catalog：它定义键集合、参数名、ICU 分支和结构；`zh-CN` 是当前旧用户
  兼容默认。两种正式目录必须键集合、具名变量、复数/选择分支和转义结构一致。
- 消息使用 `MessageDescriptor`（稳定 `MessageId` + 具名 `values`）或类型化 `t(id, values)`。
  `values` 只放消息所需的安全标量/有界参数；用户输入、业务名称、知识原文、Agent 原文、密钥、
  路径和技术日志不得进入 `id`，也不得复制进翻译目录。
- 日期、时间、数字、百分比、货币、列表、相对时间和排序使用 `Intl`/项目 formatter，并显式
  传入当前 locale、时区和业务单位。业务代码禁止固定 locale、固定时区或手工拼接自然语言。
- 复数、选择和插值使用 ICU/MessageFormat 的具名变量；禁止数字占位符、`${...}` 文案拼接、
  `item(s)` 伪复数和将 HTML/整段业务内容塞入消息资源。插值必须经过成熟 formatter 转义。

## 运行时边界

- React 组件内只能在 `AppIntlProvider` 子树中使用 `useAppIntl()`，或把 descriptor 交给已本地化
  的组件；不得在组件外调用 Hook。`useI18n()` 属于迁移期 legacy source-key facade，新代码禁止使用。
- React 组件外（Toast、原生对话框、下载、剪贴板/任务适配器）显式注入
  `createAppTranslator(locale)`；这些 sink 只接受 `MessageDescriptor`。`createToastNotifier`、
  `createUiSinks` 等 descriptor-only facade 不得接受 raw 字符串作为产品消息。
- 旧 `notify`、`data-i18n-ignore`、`src/i18n/legacy/` 和 source-key 目录只能在
  `docs/i18n/legacy-boundaries.json`/allowlist 登记的精确边界中使用。边界登记至少有 owner、
  scope、reason、telemetry、rollback boundary 和 removal conditions；checker 的每一条
  ignore/allowlist 抑制还必须有精确 fingerprint、owner、reason 和 ISO `expires`。不得为消除
  检查而新增宽泛忽略。

## 产品文本与 raw 数据

以下内容默认逐字保留：用户输入、员工/团队/知识库/文档名称和正文、引用/检索片段、Agent
原始产出、工具/provider 返回体、密钥、路径、文件名 raw 部分、技术日志、request/trace、
异常根因和第三方 iframe 内容。

需要明确标注时，前端使用 `RawContent`/`RawIdentifier`（精确 `data-i18n-raw-kind` 与
`translate="no"`），后端使用单个 JSON Pointer 的 `RawSourceMarker`。标记必须只包住 raw 值，
不能包住含相邻产品标签的父节点；JSON Pointer 不得包含通配符。raw 标记不是绕过产品消息检查
的总开关，且不把 raw 内容转成 message ID。

## 后端错误、事件与 Agent 语言

- 后端错误必须使用注册的稳定 code、具名安全 params、retryable 和 request/trace 标识；
  `message_key` 是语义键，不是自然语言。前端根据当前 UI locale 本地化，禁止展示硬编码
  中文/英文异常、`str(exc)`、provider body 或未注册 detail。
- `InternalErrorContext` 和原始根因只进入授权技术日志/诊断，不得进入公共 response、事件
  payload 或 Toast。未知/损坏错误使用安全本地化通用 fallback，并保留可诊断 request/trace。
- 系统事件/异步状态使用注册的 `event_code` 和具名 params；重放传递 code、参数、时间、关联
  ID 和必要快照，不保存依赖某一语言的最终显示文本。legacy event projection 必须有到期边界。
- UI locale 只控制产品界面、错误和事件投影；Agent reply locale 只控制新生成 Agent prose。两者
  在会话、消息、turn、任务、工具调用、流式、重试、恢复、handoff、群聊、渠道、公开运行和
  后台任务中独立传递。切换 UI locale 不得翻译用户原始内容或改写历史业务数据。
- Agent 语言必须从不可变 `LanguageContext`/持久 snapshot 读取；已绑定 session 的 reply locale
  不得被后续偏好覆盖，冲突要 fail-closed。缺失快照只可走记录过的兼容默认，不得猜测或翻译历史。

## 新增语言与翻译审核

新增正式语言前必须提交语言标签、产品范围、fallback、时区/数字/货币策略、目录、类型生成、
ICU 参数检查、伪本地化/浏览器矩阵和翻译审核负责人。流程顺序为：

1. 更新 locale registry、canonical 对等目录、类型/提取产物和 formatter 测试；不得先在业务代码
   写未登记语言。
2. 为每个新增/修改键提供语义说明、变量含义、复数/选择上下文和截图/关键路由影响；产品/语言
   审核者确认文案，开发者确认参数、转义和长度。
3. 运行目录键/ICU/参数/重复/失效/未使用/漂移检查、前后端契约检查、相关单测和构建；检查失败
   时不得用 allowlist 或删除键掩盖问题。
4. 按角色、权限、正常/空/加载/错误状态和响应式视口进行真实浏览器验收；未执行的路径标为
   `UNVERIFIED`，不能写成“已支持”。

废弃键必须先查静态使用、运行时 telemetry 和旧版本兼容需求，再标记 deprecated；连续一个
发布周期无使用且兼容边界已满足删除条件后，删除所有语言值、类型和测试，并重新运行全量检查。

## 本地检查与交付门禁

修改 UI、消息、locale、formatter、错误/事件投影或 Agent 语言路径时，至少运行并记录：

```bash
npm --prefix frontend-enterprise run i18n:check
npm --prefix frontend-enterprise test
npm --prefix frontend-enterprise run build
backend/.venv/bin/python -m pytest backend/tests
backend/.venv/bin/ruff check backend
```

可用时再运行 `npm --prefix frontend-enterprise run test:e2e:i18n`，覆盖 `zh-CN`、`en-US`、
伪本地化、非 DOM sink、iframe/postMessage 和关键角色/权限状态。依赖、浏览器、第三方渠道或
生产构建无法运行时，必须将对应结果记录为 `UNVERIFIED`；局部测试通过不等于 CI 或浏览器门禁
通过。提交前还要检查 `git diff --check` 和精确兼容 allowlist 的 owner/到期日。
