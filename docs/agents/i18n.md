# 国际化

- 开发者编写的每一处用户可见文本，必须在应用支持的每一种语言区域中完整提供。这包括 UI
  标签、状态、通知、校验消息，以及占位符、`aria-label`、`title` 和 `alt` 等无障碍文本。
- 通过既有 i18n 机制更新所有启用的翻译目录。各语言区域的插值占位符及其含义必须一致；在
  DOM 本地化之外生成文本时，使用 `useI18n().t(...)`。
- `data-i18n-ignore` 仅用于运行时或用户提供的原样内容、标识符。不得使用它、检查器排除项
  或遗漏翻译目录来绕过产品文案翻译。
- 新增语言区域或修改语言区域行为时，同时更新语言区域定义、翻译目录、校验以及对语言区域
  敏感的格式化逻辑。
- 修改 UI 或 i18n 文本时，运行
  `npm --prefix frontend-enterprise run i18n:check` 和相关前端测试，然后在切换各支持语言区域后
  验证受影响的状态。
